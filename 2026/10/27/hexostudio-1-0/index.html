HexoStudio 1.0：给自己的 Hexo 博客做一个管理后台

HexoStudio 首个正式版本发布，支持网页与桌面端，让 Hexo 博客的写作、配置和 Git 管理更方便。

一直在用 Hexo 写博客，我喜欢它的简单：文章是 Markdown 文件，配置放在项目里，源码可以交给 Git 管理。

不过，日常维护也有一些反复操作。写文章要打开编辑器，插图要处理文件和路径，调整主题要找到对应配置，写完还要提交、推送和部署。换一台电脑，往往又要准备一套环境。

参考 Qexo、HexoHub 的使用方式，我开始给自己的博客做一个管理后台，希望把这些常用操作集中起来。经过几轮开发和调整，HexoStudio 1.0.0 正式发布了。

让写作和博客管理集中在一个工作台里

HexoStudio 是一个面向 Hexo 的内容管理工具，支持网页、本机服务，以及 macOS、Windows 桌面程序。

你可以连接电脑上的 Hexo 源码目录，也可以通过 GitHub、GitLab 的访问 Token 连接远端仓库。已有博客可以继续使用自己的主题和部署方式，文章仍然保存在 Hexo 项目中。

目前最常用的文章、页面和配置管理已经具备。

文章编辑器支持 Markdown 实时预览、快捷保存，以及图片粘贴和拖拽上传。文章与草稿分别管理，也可以搜索、筛选和排序。关于页、友链页等独立页面，则放在页面管理中编辑。

写作时，标题、日期、标签和分类可以直接填写。封面与主题参数也有单独入口，不必每次都手动修改文首 YAML。

例如，我使用的 Morii 主题可以通过这些字段控制文章展示：

自定义参数支持文本、布尔值、数字和嵌套 YAML，显示效果由主题决定。修改后先应用到编辑器，再保存文章，方便检查实际写入的内容。

保留自己熟悉的 Git 工作流

本机模式下，HexoStudio 提供变更查看、差异比较、暂存、提交、拉取和推送操作。连接远端仓库时，会在运行 HexoStudio 的机器上建立工作副本。

云端模式则通过仓库 API 读写文件，每次保存直接生成提交，可以交给博客仓库已有的自动化流程完成构建和部署。

这里需要区分一下：保存文章表示内容已写入文件或仓库，线上博客是否更新，取决于后续部署流程。使用 HexoStudio 时，仍然可以保留原来的 GitHub Actions 或其他构建方式。

AI 写作作为可选能力

1.0 也加入了 AI 辅助写作，可以生成文章、大纲，或者润色选中的文字。

服务地址、模型和 API Key 由用户自行配置，支持兼容 OpenAI 接口的服务。生成结果需要查看并确认后再插入正文，也可以保存为草稿，不会直接发布到博客。

对我来说，它比较适合帮助整理提纲、调整表达。文章里的事实、代码示例和个人观点，仍然需要自己检查。

在本机运行，或部署成随时可访问的网站

如果已经安装 Node.js 22.12 或更新版本，可以通过 npm 启动：

随后打开：

首次使用按照向导完成三步：

  1. 连接 PostgreSQL、MySQL 或 MongoDB。
  2. 创建管理员账号。
  3. 连接本机博客目录或远端仓库。

数据库用于保存管理员账号等管理数据，博客正文仍保存在 Hexo 项目或仓库中。本机运行也需要准备账号数据库。

喜欢桌面程序的话，可以从 GitHub Releases 下载 macOS 或 Windows 安装包。当前桌面包尚未配置开发者签名和 macOS 公证。

如果希望在其他电脑或手机上管理博客，也可以部署网页版。项目提供了 Vercel、Netlify、Render、Railway 和 Docker 的部署配置，具体环境变量和初始化步骤可以参考云端部署文档。

界面支持深色、浅色和跟随系统，也提供简体中文与 English，并对手机布局做了适配。

从自己的需求出发，继续慢慢完善

做这个项目的过程中，我花了不少时间调整配置向导、表单长度、下拉选择框和手机布局。功能接通之后，真正每天使用，才会发现哪些步骤繁琐、哪些提示不清楚。

1.0 先把写作、页面、配置和仓库管理串了起来。目前图片上传仍保存在博客项目或仓库中，独立图床还没有接入。后续会继续完善命令行和写作体验，让常用操作更顺手。
